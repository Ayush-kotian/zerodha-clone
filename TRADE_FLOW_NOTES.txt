ZERODHA CLONE TRADE FLOW NOTES
==============================

This file explains:
1. What your original code was doing
2. What was wrong or incomplete
3. What was modified
4. How the updated logic now works


1. YOUR ORIGINAL LOGIC
----------------------

Watchlist:
- You had Buy and Sell buttons on each watchlist stock.
- Clicking Buy opened the buy popup.
- Clicking Sell opened the sell popup.

Buy popup:
- User entered quantity and price.
- Frontend sent this data to backend `/newOrder`.
- Backend created an order.
- Backend also created a new holding row for that stock.

Sell popup:
- User entered only quantity.
- Frontend sent only quantity and stock name to backend.
- Backend checked holdings and reduced quantity using FIFO logic.
- But sell order price was not properly handled.

Holdings page:
- It fetched holdings only once when page loaded.
- After buy/sell, the page did not refresh automatically.

Orders page:
- It was only a placeholder.
- It did not show actual placed orders.

Popup drag logic:
- It worked.
- But event listeners were attached again on every render.


2. MAIN PROBLEMS IN ORIGINAL VERSION
------------------------------------

Problem 1:
- Backend saved sell order before fully validating sell.
- So even failed sells could create an order record.

Problem 2:
- No proper input validation.
- User could try bad values like 0, empty price, negative qty.

Problem 3:
- Sell order price was stored as 0.
- So order history was incomplete and unrealistic.

Problem 4:
- Holdings screen did not update after trade unless page was reloaded.

Problem 5:
- Orders screen did not show actual order history.

Problem 6:
- Popup drag `useEffect` had no stable dependency handling.


3. WHAT WAS MODIFIED
--------------------

A. Backend changes
File: backend/index.js

Added:
- GET `/allOrders`
  This returns all saved orders.

Changed validation in POST `/newOrder`:
- Validates stock name
- Validates order mode is BUY or SELL
- Validates quantity > 0
- Validates price > 0 for both BUY and SELL

Changed sell flow:
- First checks whether enough shares exist
- Only then reduces holdings
- Only after successful validation/trade, saves the order

Changed order saving:
- BUY order saves actual buy price
- SELL order now also saves actual sell price
- Earlier SELL price was stored as 0


B. Context changes
File: dashboard/src/components/GeneralContext.js

Added:
- `refreshKey`
- `refreshTradingData()`

Why:
- When a trade succeeds, frontend needs a way to tell holdings/orders to fetch new data.

Also changed:
- Sell popup now receives `initialPrice`
- This initial price comes from watchlist current stock price


C. Dashboard structure change
File: dashboard/src/components/Dashboard.js

Changed:
- `GeneralContextProvider` now wraps both WatchList and routed pages

Why:
- Earlier only WatchList was inside the provider
- Holdings and Orders could not access refresh context properly


D. Buy popup changes
File: dashboard/src/components/BuyActionWindow.js

Earlier:
- Quantity and price were sent directly
- No proper frontend validation
- Errors were not handled well

Now:
- Validates quantity > 0
- Validates price > 0
- Shows error message if input is wrong
- On success:
  - places order
  - triggers refresh
  - closes popup after short delay

Also improved:
- Drag listeners are attached and cleaned up properly


E. Sell popup changes
File: dashboard/src/components/SellWindow.js

Earlier:
- User entered only quantity
- Sell price was missing
- Backend stored price 0

Now:
- Sell popup has quantity field and price field
- Price is prefilled from watchlist stock price
- User can edit the price
- Validates quantity > 0
- Validates price > 0
- On success:
  - places sell order with actual price
  - triggers refresh
  - closes popup after short delay

Also improved:
- Drag listeners are attached and cleaned up properly


F. Watchlist changes
File: dashboard/src/components/WatchList.js

Earlier:
- Sell button only passed stock name

Now:
- Sell button passes:
  - stock name
  - stock current watchlist price

Why:
- Sell popup needs current price as default value


G. Holdings page changes
File: dashboard/src/components/Holdings.js

Earlier:
- Data fetched only once on mount
- Summary values were hardcoded

Now:
- Refetches data when `refreshKey` changes
- Computes:
  - total investment
  - current value
  - P&L
  from real holdings data


H. Orders page changes
File: dashboard/src/components/Orders.js

Earlier:
- Static placeholder page only

Now:
- Fetches data from `/allOrders`
- Shows real orders in a table
- Refetches when `refreshKey` changes


4. UPDATED FLOW IN SIMPLE WORDS
-------------------------------

BUY FLOW:
1. User clicks Buy from watchlist
2. Buy popup opens
3. User enters qty and price
4. Frontend validates values
5. Backend validates again
6. Backend creates holding
7. Backend saves buy order
8. Frontend refreshes holdings/orders

SELL FLOW:
1. User clicks Sell from watchlist
2. Watchlist sends stock name + current stock price
3. Sell popup opens with default price already filled
4. User enters qty and can edit price
5. Frontend validates values
6. Backend validates values again
7. Backend checks if enough shares exist
8. Backend reduces holdings using FIFO
9. Backend saves sell order with real sell price
10. Frontend refreshes holdings/orders
